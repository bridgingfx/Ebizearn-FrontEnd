## 1. Summary

Today's work focused on three areas:

1. **Access control.** Super Admin can now control platform access sidebar section by sidebar section for every role (Admin, Moderator, Business, Contributor). Super Admin can also assign specific users to individual admins and moderators.

## 2. Features Delivered

### 2.1 Roles & Permissions by sidebar section

- Every admin sidebar page has its own permission:
  - Users, Businesses, KYC, Social Channels
  - Deposits, Withdrawals, Wallets
  - Fraud & Risk, Referrals, Demo Requests
  - Analytics, Website Traffic, System Health, Audit Logs
  - and the remaining pages.
- Super Admin can switch each page on or off per role or per individual account. The sidebar shows only the pages a person is allowed to use, and the API enforces the same rules.
- Platforms, Payment Gateways, Email & Campaigns and Contributor Ranks remain Super Admin only.
- **Controlled delegation:**
  - An admin can grant access to the users below them only from the permissions the admin holds.
  - A moderator can do the same for their own contributors and businesses.
  - Neither can change the admin role or other staff accounts.
- **No disruption on release:** existing grants were copied into the new permissions, so nobody gains or loses access when this goes live.

### 2.2 Assigning users to admins and moderators

- Super Admin can assign businesses, contributors and moderators to a specific admin. Businesses and contributors can be assigned to a moderator.
- An admin or moderator with assigned users sees and manages only those users and their data: KYC, withdrawals, deposits, wallets, support tickets, campaigns and tasks.
- The user list shows "Managed by …" for each assigned user.

### 2.3 Wallet adjustments

- A new **Add / remove wallet money** permission was added. Only Super Admin has it by default, and it can be granted to selected admins.
- Every manual credit or debit requires a reason and is recorded in the audit log.

### 2.4 Business Team Access

- **Adding members:** the business owner adds team members on the Team Access page (name, email, password).
- **Choosing access:** the owner selects which sections each member can use (Campaigns, Task Library, Proof Gallery, Analytics, Billing, Support).
- **Limits on access:**
  - A member can never have more access than the owner.
  - If Super Admin removes a permission from the owner, all of that owner's members lose it too.
- **Shared account:**
  - Members sign in through the normal business login page (`/business/login`). Forgot-password works for them as usual.
  - Members work inside the owner's business account, and all their work appears in the owner's account.
  - A member's email address cannot be used to register a new account.
- **Managing members:** the owner can suspend, reactivate or remove a member at any time. Members are blocked automatically if the owner's account is suspended.
- **Business sidebar:** the business sidebar now follows the same permission rules, so each section appears only when allowed.

### 2.5 Activity attribution ("created by")

- Campaigns, tasks and deposit requests now record which account created them.
- The business owner, Admin and Super Admin can see this as **"by {name} · Team member / Owner"**. This clearly separates the owner's actions from a team member's or staff member's.
- Proof reviews already recorded the reviewer's name.

### 2.6 Country change compliance

- When a contributor changes their country of residence, the change is sent to staff for approval.
- After approval, the contributor must complete KYC again for the new country.

## 5. Deployment Steps (Backend)

The frontend deploys automatically from `main`. For the backend, run the following on the server:

```bash
cd ~/repositories/Ebizearn-BackEnd && git pull
# copy the files to ~/public_html/api.ebizearn.com (standard deployment step)
php artisan migrate --force
php artisan config:clear && php artisan route:clear && php artisan cache:clear
```

New database changes in this release:

- Country change requests.
- Sidebar section permissions.
- Staff user assignments.
- Business team members and business section permissions.
- A "created by" field on campaigns, tasks and deposit requests.
