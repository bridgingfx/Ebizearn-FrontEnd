### 2.4 Automatic proof check: AI + official Instagram API

- **How the AI is used:**
  - Right after a contributor submits proof, the AI looks at the screenshot and compares it with the task requirements.
  - It uses the OpenAI or Gemini account set in Admin → Settings → AI.
- **Instagram post tasks:**
  - If the proof link is an Instagram post or reel, the server reads the post through Instagram's **official API**.
  - It confirms that the post:
    - exists on the contributor's connected account;
    - was published after they took the task;
    - contains the required text and hashtags.
- **Approval rule:**
  - A task is approved automatically **only when the API and the AI both confirm it**.
  - A screenshot alone never approves a task.
  - Anything uncertain goes to manual review with the reason shown: AI not confident, Instagram not connected, connection expired, caption doesn't match, or API unavailable.
- **Manual review still works for every task** (Verification Center and Task History). For other platforms, the AI result is shown to the reviewer as advice.
- **Note on OpenAI and Instagram:** OpenAI cannot log in to Instagram or read accounts. The server reads the post through the contributor's authorised Instagram connection, and the AI only compares the evidence the server gives it.

### 2.5 Pending reward for the task duration, final check, release or refund

- **On approval:**
  - The reward goes to the contributor's **pending balance only**, not the withdrawable balance.
  - The system records which business wallet funded it and the final check date.
  - The rank bonus also waits for the same period. Before this change, the bonus could be withdrawn immediately.
- **At the end of the duration** (checked hourly), the post is read again:
  - **Post still live:** the reward is released to the available balance, exactly once. The contributor and the business are notified.
  - **Post deleted, archived or changed:** the reward is cancelled and returned to the business that funded it (campaign budget, or the business balance if the campaign has ended). The contributor and the business are notified.
  - **Could not confirm** (Instagram down, connection expired): nothing is assumed. The reward stays pending and the check is retried every 6 hours. After 5 attempts the task moves to "Reverification required" for an admin to decide.
- **Admin controls in Task History:**
  - Release reward, Refund to funder, Re-check post now, Run automatic check.
  - Each action requires a reason and is recorded in the audit log.
  - The page also shows the full verification history, the funding business and the money trail.
- **Safety:** release and refund are protected against duplicates (row locking and one-time keys). Repeated jobs, double clicks or simultaneous runs cannot pay or refund twice.

### 2.9 Demo data cleanup

- **Cause:** the database setup script itself created demo data, and running it again would have re-created that data on the live server. The demo data was:
  - five sample campaigns with tasks;
  - a sample proof submission;
  - a fake wallet history for the demo contributor ($28.40 balance, a sample withdrawal "to Bank Account ****4821", sample rewards).
- **Setup script:** it now creates demo data **only for automated tests** (or when explicitly enabled for a local demo). On a server it only creates accounts and configuration.
- **New cleanup command** `php artisan cleanup:demo-data`:
  - It removes only records that exactly match the seeded demo data.
  - Wallets left with no transactions are reset to zero, and contributor statistics are recalculated from real history.
  - It is a **dry run by default**: it lists what it would remove and changes nothing. `--force` performs the cleanup in a single database transaction.
  - Campaigns that only *look* like test data ("test", "dummy" in the title) are listed separately and removed only with `--include-marked`.
- **Always kept:**
  - every user account (contributor, business, admin, super admin) with its login, profile and permissions;
  - task categories, task types and Task Library templates;
  - all settings;
  - every genuine campaign, task and payment.
- The local development database was checked: it already contains no demo task or payment data. The cleanup must be run on the live server (see Section 5).

## 5. Deployment Steps (Backend)

The frontend deploys automatically from `main`. For the backend, in cPanel:

1. **Git Version Control** → **Update from Remote** → **Deploy HEAD Commit**. The deployment runs the migrations and clears the caches.
2. **Server `.env`:** set `AI_VERIFICATION_PROVIDER=auto`. The other `IG_*` settings have safe defaults (see `.env.example`).
3. **Cron:** make sure `* * * * * php artisan schedule:run` is active. Final checks, reward release and refunds, the automatic proof check and new-task emails all depend on it.
4. **AI:** confirm Admin → Settings → AI has an OpenAI key and is enabled.
5. **PHP upload limits:** set `upload_max_filesize` and `post_max_size` to at least 100M for campaign videos.
6. **Meta Developers (Instagram):**
   - Create a Business app and add the Instagram product ("API setup with Instagram login").
   - Enter the app ID and secret in Admin → Settings → Social connect.
   - Register the redirect address shown there.
   - Request the `instagram_business_basic` permission. **Meta App Review** is required before ordinary users can connect; until then, only test users added to the app can.
7. **Demo data cleanup (live server):**
   - Run `php artisan cleanup:demo-data` (dry run) and review the list.
   - Then run `php artisan cleanup:demo-data --force`.
   - Add `--include-marked` only if the listed "looks like test data" campaigns should also go.

New database changes in this release:

- Verification history, and reward tracking on submissions (pending / released / refunded, funding source, final check date).
- The permissions granted for social connections.
